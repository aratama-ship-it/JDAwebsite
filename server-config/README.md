## 通常公開との境界

- 通常のサイト公開候補に `.htaccess` を含めない。
- `scripts/prepare_release.sh` の既存の禁止判定を維持する。
- Cyberduckでは同期や一括削除を使わず、承認された列挙ファイルだけをアップロードする。
- `.htaccess` の新設・変更は、通常ページの公開とは分けた専用作業として本人の明示承認後に行う。

## 将来のクリーンURL切替案

`proposals/clean-url-cutover.conf` は、以前プロジェクトルートに置かれていた未公開の `.htaccess` 案を、誤アップロード防止のため非アクティブな名前で保存したもの。

- 元ファイルのSHA-256: `5bfeb9b9bd19581b5f09f667795ef4bda2a3a257204cdd55b164882761cfe010`
- 現在の用途: 将来案の保管のみ。
- そのまま本番へアップロードしない。
- `/champions/` など転送先が本番でHTTP 200になる前に有効化しない。

有効化を検討するときは、次を別工程で行う。

1. 公開ルートと変更対象のバックアップおよび復元手順を確認する。
2. 全転送先の公開とHTTP 200を確認する。
3. ルールをテスト環境または限定的な方法で検証する。
4. `.htaccess` だけを対象にした変更内容とロールバック手順を提示し、本人の承認を得る。
5. 旧URLが1回の301で着地し、`AJDC/`、`OIDC/`、`TIDC/`、`wp/` に影響しないことを確認する。
