# JDA本体 ロリポップ切替・ロールバック手順

作成日: 2026-08-22

## 現在の状態

- `diabolo.jp`はロリポップ環境を使用している。
- ロリポップの公開（アップロード）フォルダは管理画面から変更できる。
- 管理画面はログイン画面まで確認したが、ログイン済みセッションがないため、契約プラン、現在の公開フォルダ、空き容量、バックアップ設定、FTPS情報は未確認。
- 独自ドメイン設定の解除は行わない。解除と公開フォルダの変更は別操作で、解除すると独自ドメインのメールアドレス等にも影響する。

## 採用する切替方式

現行公開フォルダを直接上書きせず、日付付きの新しい公開候補フォルダを作る。AJDC/OIDC/TIDCと保全対象を新フォルダ側でも確認できる状態にした後、ロリポップの「独自ドメイン設定」で`diabolo.jp`の公開フォルダだけを切り替える。

推奨フォルダ名の例:

```text
jda-current-20260822/   切替前の現行公開フォルダ（実際の名称を管理画面で記録）
jda-next-20260822/      新しい公開候補
```

実際の現行公開フォルダを推測で改名しない。管理画面の表示とFTPS上の絶対位置を確認して記録する。

## 切替前に管理画面で記録する項目

- [ ] 契約プランと契約期限
- [ ] Web・メール・DBを含む使用量と空き容量
- [ ] `diabolo.jp`の現在の公開（アップロード）フォルダ
- [ ] `www.diabolo.jp`の扱い
- [ ] サブドメインと各公開フォルダ
- [ ] FTPSサーバー名、アカウント名、接続元IP制限の有無
- [ ] バックアップオプションの契約状態と復元可能日
- [ ] MySQLデータベース一覧とAJDC/OIDCに対応するDB
- [ ] cron・PHPバージョン・WAF・アクセス制限設定

秘密情報そのものはGit、Markdown、スクリーンショットへ保存しない。保管場所と担当者だけを記録する。

## バックアップ

切替直前に同じ時点のWebファイルとDBを取得する。

1. FTPSで現在の公開フォルダ全体を日付付きローカル保管場所へダウンロードする。
2. AJDC/OIDC等が利用するMySQLを管理画面からエクスポートする。
3. 公開フォルダ設定、サブドメイン、PHP、cron、バックアップ設定を画面またはテキストで記録する。秘密値は伏せる。
4. Webバックアップのファイル数、合計サイズ、トップ階層、更新日時を`docs/JDA_LEGACY_SERVER_AUDIT.md`のローカルスナップショットと比較する。
5. 復元先を作れる空き容量があること、DBエクスポートを読み戻せることを確認する。

バックアップオプション未契約時にサーバー会社側の復旧データを依頼できる場合もあるが、希望時点を必ず復旧できる保証はないため、切替前の自主バックアップを省略しない。

## 新しい公開候補

1. `scripts/build-jda-release.sh`で74ファイルのJDA本体releaseを生成する。
2. 新しい空の`jda-next-YYYYMMDD/`へreleaseをアップロードする。
3. `deploy/jda-legacy-never-copy.txt`のPHP、テスト環境、不審な旧`sitemap.xml`を入れない。
4. `deploy/jda-preserve-paths.txt`のURLを消さないため、次を別の承認済み保全パッケージとして用意する。
   - AJDC
   - OIDC
   - TIDC
   - 過去イベント記事と依存画像/PDF
   - オンラインコーチング、1分トラック等の継続対象
5. AJDC/OIDCのWordPressを一時継続する場合は、対応DB、`wp-config.php`、uploads、PHP本体を大会ごとの閉じた単位で保全する。旧ルートの`wp/`や`test/`を混ぜない。
6. TIDCの旧`send.php`はそのまま再公開せず、問い合わせ機能の利用状況を確認して代替または無効化する。

AJDC/OIDC/TIDCの保全パッケージと同URL動作が確認できるまでは、公開フォルダを切り替えない。

## 事前検証

- [ ] 一時URLまたはロリポップ！アドレスでトップと通常下層10ページを確認
- [ ] CSS、JS、画像、PDF、MP3が200
- [ ] `/AJDC/`、`/OIDC/`、`/TIDC/`が同じURLで表示
- [ ] 既知の旧URLが予定した301先へ転送
- [ ] `/send.php`、`/test/`、`/wp/`、内部Markdownが公開されない
- [ ] 新しい正規`sitemap.xml`と`robots.txt`だけが存在
- [ ] FormSubmitは本番ドメインで有効化済み
- [ ] HTTP/HTTPSとwwwの正規化を検証

## 本番切替

1. 更新を止め、切替直前の差分バックアップを取る。
2. 新公開候補の最終ハッシュ・ファイル数を確認する。
3. ロリポップの独自ドメイン設定で`diabolo.jp`の公開フォルダを新候補へ変更する。
4. 独自ドメイン設定の解除、DNS変更、メール設定変更は行わない。
5. トップ、下層、AJDC/OIDC/TIDC、PDF、旧URL、フォームを確認する。
6. アクセスログ、404、メール受信、Search Consoleを監視する。

## ロールバック

次のいずれかが発生したら、コンテンツ修正を本番上で続けずロールバックする。

- AJDC/OIDC/TIDCが表示できない
- CSS/JS/PDF等の主要資産が連続して404
- フォームが送信不能、または宛先が不正
- 500系エラー、著しい表示崩れ、予期しないPHP実行

手順:

1. 管理画面で`diabolo.jp`の公開フォルダを、事前に記録した旧フォルダへ戻す。
2. DNSや独自ドメイン設定の解除は行わない。
3. トップ、AJDC/OIDC/TIDC、メール受信を確認する。
4. 障害時刻、URL、HTTP状態、変更内容を記録する。
5. 原因を修正した新しい公開候補を別名で作り、同じ検証を最初から行う。

## 管理画面ログイン後の完了条件

この手順の項目2を完了扱いにできるのは、次がすべて埋まった時点。

- 現在の公開フォルダ名
- 新しい公開候補フォルダ名
- Web＋DBバックアップの保管場所と復元確認
- AJDC/OIDC/TIDC保全方式
- 切替担当者とロールバック判断者
- 切替予定日時
